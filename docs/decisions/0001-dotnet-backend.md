# 0001 バックエンドを ASP.NET Core と C# で作り直す

決めた日: 2026-10-17

## 状況

バックエンドは、Spring Boot(Java)で作った後、2026-07 に NestJS(TypeScript)へ移していた。
Gateway は ASP.NET Core(C#)で動いている。
バックエンドを今後どの技術で育てるかを決める必要があった。

## 決めたこと

NestJS のバックエンドを消し、ASP.NET Core 10 の Minimal API と C# で作り直す。

## 理由

- 利用者がバックエンドを .NET で書くことを選んだ。
- Gateway と同じ言語、同じランタイム、同じ SDK のコンテナでビルドとテストを走らせられる。サーバー側の道具が 1 つに減る。
- Gateway と同じ書き方(Minimal API)で、層の分け方と例外の扱いをそろえられる。

## 却下した案

- **NestJS のまま育てる**: 動くものがすでにある。サーバー側に Node と .NET の 2 つの道具が残る。利用者が .NET を選んだ。
- **Spring Boot に戻す**: 旧版の設計書が残っている。Java の道具がもう 1 つ増え、移した理由とも逆になる。

## 影響

- `backend/` を消した。段階 0 の終わりまで、バックエンドは動かない。
- 旧版の SQL(V1 から V11)と初期データは、コミット `6529442` から EF Core のマイグレーションへ移す([0003](0003-ef-core-migrations.md))。
- `CLAUDE.md`、`.claude/` のコマンドと Skill を .NET の前提に書き直した。
