# 0002 Gateway とバックエンドを 1 つにまとめない

決めた日: 2026-10-17

## 状況

バックエンドを .NET で作り直す([0001](0001-dotnet-backend.md))と、Gateway とバックエンドが同じ言語になる。
1 つの ASP.NET Core のアプリにまとめるか、今のとおり 2 つのコンテナに分けるかを決める必要があった。

## 決めたこと

Gateway(8080)とバックエンド(8081)を分けたままにする。
バックエンドは `X-Service-Key` のない要求を拒む。

## 理由

- 利用者が分けたままにすることを選んだ。
- 入口の仕事(CORS、トークン、振り分け)と業務の仕事を、別の理由で変えられる。管理者の確かめ方(未決)を足すときに、バックエンドに手を入れずに済む。
- 今の `CLAUDE.md` の構成と、`X-Service-Key` によるサービス間の認証をそのまま使える。

## 却下した案

- **1 つのアプリにまとめる**: コンテナが 1 つ減り、YARP とサービス間のキーが要らなくなる。入口と業務の境目がコードの中の約束だけになり、管理の API の守りを足すときに業務のコードに手が入る。

## 影響

- 画面から見える API のパスは、Gateway の振り分け(`/api/v1/{**catch-all}`)で決まる。
- Gateway からバックエンドへの呼び出しの 1 段だけ、応答が遅くなる。測っていない。
- バックエンドを Gateway の外に出さない決まり(ポートを公開しない)を守り続ける必要がある。
