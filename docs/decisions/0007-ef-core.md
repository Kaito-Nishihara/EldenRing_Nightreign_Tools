# 0007 データベースのアクセスに EF Core を使う

決めた日: 2026-10-17

## 状況

.NET のバックエンドで、PostgreSQL への読み書きに何を使うかを決める必要があった。

## 決めたこと

EF Core(Npgsql)を使う。
サービスからは、リポジトリのインターフェースを通して使う。

## 理由

- 利用者が EF Core を選んだ。
- パターン検索の結合(記録、収縮先、収縮候補地)を `Include` で書け、まとめる処理を LINQ で書ける。
- マイグレーションも同じ道具で管理できる([0003](0003-ef-core-migrations.md))。

## 却下した案

- **Dapper**: 軽く、SQL をそのまま書ける。エンティティと結果の対応を自分で書き、テーブルの形を SQL とコードの 2 か所で持つことになる。

## 影響

- サービスに EF Core を見せない決まり(`AC-SVC-06`)を守る必要がある。
- 重いクエリが要るときは、リポジトリの中で `FromSql` を使ってよい。
