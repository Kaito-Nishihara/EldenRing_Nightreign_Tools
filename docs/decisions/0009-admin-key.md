# 0009 管理者を Gateway で管理用の鍵により確かめる

決めた日: 2026-10-17

## 状況

旧版では、管理用の API(`/api/v1/admin`)を誰でも呼べた。
Gateway は JWT を発行していたが、どの API もトークンを求めていなかった。
管理者をどう確かめるかを決める必要があった。

## 決めたこと

Gateway が、`/api/v1/admin` の下への要求に `X-Admin-Key` の見出しを求め、環境変数 `ADMIN_KEY` の値と比べる。

## 理由

- 利用者が選んだ。
- 管理者は 1 人か数人で、利用者のアカウントを持たない(要件定義の 2.2)。鍵 1 つで足りる。
- Gateway だけで完結し、バックエンドに手を入れずに済む(決定の記録 [0002](0002-keep-gateway-separate.md))。
- 公開した環境でも、プレイ中にスマートフォンから座標を直せる。

## 却下した案

- **JWT に管理者の役割を入れ、ログインで発行する**: 役割を細かく分けられる。ログインの画面と、管理者の名前と合言葉を持つ場所が要り、管理者が 1 人の今は仕組みが重い。
- **公開する環境では管理用のパスを振り分けない**: 鍵を持たずに済む。公開した環境で座標を直せず、手元のデータベースから公開先へマスタを移す手順が要る。

## 影響

- Gateway に環境変数 `ADMIN_KEY` を足す。16 文字より短いか、ないときは、Gateway の起動を止める。
- Gateway は、`/api/v1/admin` の下への要求の回数を、送り元の IP ごとに 1 分 60 回までに抑える。鍵を総当たりで試されることを防ぐためである。
- Gateway は `X-Admin-Key` を消してからバックエンドへ渡す。バックエンドは管理者を確かめず、サービス間キーで Gateway を通ったことだけを確かめる。
- 鍵は見出しに平文で載るので、手元の外に公開するときは HTTPS で配る。
- 管理の画面は、鍵を `sessionStorage` に持つ。タブを閉じると消える。
- `JWT_SECRET` と `/auth/token` は使い道がなくなるので、段階 0 で外す(#50)。
- 管理者を複数の人に分けて、誰が直したかを残したくなったら、JWT の案で見直す。
