# 共通設計: 画面の共通仕様

## 1. 目的

どの画面も、同じ見た目と同じ動きで作れるようにする。
見た目は、エルデンリング ナイトレインの世界に合わせる。
夜の暗い地に黄金樹の金を灯し、収縮(夜の雨)を青紫で表す。
API が失敗したときの動きを 1 か所で決め、画面ごとに違う扱いにならないようにする。

## 2. 範囲

やること:

- 色、書体、余白、装飾の値(Tailwind のテーマ)
- 画面の幅の区切りと、全体のレイアウト
- 共通の部品と、それぞれの状態
- マップの描き方の共通の決まり
- 読み込み中、空、エラー、保存中の表し方
- API を呼ぶクライアントとエラーの扱い
- アクセシビリティの決まり
- ディレクトリと名前の付け方

やらないこと:

- 画面の一覧と移り方。「画面の一覧と遷移」に書く
- 個々の画面の項目と操作。機能ごとの仕様書に書く
- 明るい配色。暗い配色だけを作る。ゲームの画面と並べて、夜に使うことが多いためである
- ゲームの画像素材のうち、ロゴと UI の部品の流用。見た目は色、書体、線で寄せる。マップ画像と開始地点のアイコンは、旧版から `frontend/public` にあるものを使う(決定の記録 [0016](../decisions/0016-publish-game-images.md))

### この文書で使う言葉

| 言葉 | 意味 |
|---|---|
| テーマ | Tailwind CSS に登録する色、書体、余白などの値の一覧。部品はこの一覧の名前で値を使う |
| 部品 | 画面を組み立てる単位。React のコンポーネント |
| 区切り | 画面の幅がその値以上になったら並べ方を変える境目の幅 |
| 飾り枠 | パネルの四隅に置く金の鉤形の線。ゲームのメニューの枠に寄せる装飾 |
| 骨組みの表示 | 読み込みが終わるまで、内容が入る場所に出す枠(スケルトン) |
| ボトムシート | 狭い画面で、下から引き出して使う操作の枠 |
| コントラスト比 | 文字の色と地の色の明るさの差を表す数。1 から 21 で、大きいほど読みやすい |

## 3. 画面

### 3.1 見た目の方針

| 方針 | 具体的なこと |
|---|---|
| 夜の地 | 地はほぼ黒の焦げ茶にする。真っ黒にしない。画面の上の端に、金の光が薄く差すぼかしを重ねる |
| 金で導く | 主の操作、選んだ状態、見出しを金にする。金は面積を小さく使い、1 画面で目が行く場所を絞る |
| 夜の雨は青紫 | 収縮の円と、収縮の外の暗がりを青紫にする。金と混ぜない |
| 碑文の書体 | 見出しは明朝、英字の飾りは Cinzel(碑文風のローマン体)にする |
| 細い線と飾り枠 | 枠は 1px の細い線にし、主なパネルだけ四隅に飾り枠を付ける。角は丸めない |
| 静かな動き | 動きは光の強さと透明度の変化だけにし、跳ねたり揺れたりさせない |

### 3.2 色

部品には色の値を直接書かず、テーマの名前で指定する。
例: 主のボタンは `bg-gold text-night` と書く。
`bg-[#c9a45c]` とは書かない。

| 名前 | 値 | 使いどころ |
|---|---|---|
| `night` | `#0e0c0a` | ページの地 |
| `night-raised` | `#1a1612` | パネル、カード、入力欄の地 |
| `night-sunk` | `#24201a` | 選んだ行の地、骨組みの表示、押している間のボタン |
| `ash` | `#e8dfcc` | 本文の文字 |
| `ash-soft` | `#a89c86` | 補足の文字、使えない状態の文字 |
| `gold` | `#c9a45c` | 主のボタンの地、選んだ状態の印、リンク |
| `gold-bright` | `#e6c886` | 見出し、フォーカスの輪郭、触れたときの金 |
| `gold-deep` | `#8a6d32` | 飾り枠、飾りの区切り線 |
| `ember` | `#d0654a` | エラーの文字と枠、非表示にするボタン |
| `ember-soft` | `#3a1d16` | エラーの知らせの地 |
| `tide` | `#8c7cf0` | 収縮の円の線、夜の雨に関わる印 |
| `tide-soft` | `#221d3d` | 夜の雨に関わる知らせの地 |
| `grace` | `#9cc08a` | 保存できた印、成功の知らせ(祝福の緑) |
| `line` | `#3a3226` | 飾りの区切り線、表の罫 |
| `line-strong` | `#7a6a4e` | 入力欄とボタンの枠 |
| `abyss` | `#07060a` | マップの画像の下の地。マップの画像の背景は透けているので、`night` より暗い地を敷く |

ページの地には、次の 2 つを重ねる。

- 上の端の中央から広がる、金の薄いぼかし(`radial-gradient`、不透明度 0.08)。
- 細かい粒の模様(不透明度 0.03)。のっぺりした黒にしないためである。

#### 色の組み合わせの決まり

文字は地とのコントラスト比を 4.5 以上、枠やアイコンのように形で意味を伝えるものは 3 以上にする。
この 2 つの数は、WCAG 2.2 の達成基準 1.4.3 と 1.4.11 の値である。

次の表は、上の値から計算したコントラスト比である。

| 文字や枠 | 地 | 比 | 使ってよいか |
|---|---|---|---|
| `ash` | `night`、`night-raised`、`night-sunk` | 14.7、13.6、12.2 | よい |
| `ash-soft` | `night`、`night-raised`、`night-sunk` | 7.2、6.7、6.0 | よい |
| `gold` | `night`、`night-raised`、`night-sunk` | 8.3、7.7、6.9 | よい |
| `gold-bright` | `night`、`night-raised`、`night-sunk` | 12.1、11.1、10.0 | よい |
| `night` | `gold`、`gold-bright` | 8.3、12.1 | よい。主のボタンの文字 |
| `ember` | `night`、`night-raised` | 5.2、4.8 | よい |
| `ember` | `night-sunk`、`ember-soft` | 4.4、4.1 | 文字には使わない。`ash` を使う |
| `ash` | `ember-soft`、`tide-soft` | 11.6、12.1 | よい |
| `tide` | `night`、`night-raised`、`night-sunk` | 5.8、5.4、4.8 | よい |
| `grace` | `night`、`night-raised` | 9.6、8.8 | よい |
| `line-strong` | `night`、`night-raised`、`night-sunk` | 3.7、3.4、3.1 | 入力欄とボタンの枠に使う |
| `gold-deep` | `night`、`night-raised` | 4.0、3.7 | 飾り枠に使う。文字には使わない |
| `line` | `night`、`night-raised` | 1.5、1.4 | 飾りの区切り線だけに使う |

この表にない組み合わせを使うときは、比を計算して、この表に足す。

#### パターンの色

パターンの色分けには、色覚の多様性に配慮した Paul Tol の 8 色の組(今の `getPatternColor`)を使う。

| 順 | 値 | `night` との比 |
|---|---|---|
| 1 | `#4477AA` | 4.2 |
| 2 | `#EE6677` | 6.3 |
| 3 | `#228833` | 4.3 |
| 4 | `#CCBB44` | 10.0 |
| 5 | `#66CCEE` | 10.6 |
| 6 | `#AA3377` | 3.2 |
| 7 | `#BBBBBB` | 10.2 |
| 8 | `#EE7733` | 6.8 |

Konva でマップを描くときは CSS の変数を読めないので、色の値は `frontend/src/lib/theme.ts` の定数から取る。
`lib/theme.ts` の値は `globals.css` の `@theme` と同じにし、テストで食い違いを確かめる。

どの色も、線と円としては 3 以上の比がある。
文字には使わない。
パターンの番号は、色の丸の中に `night` の文字で書く。
色だけでパターンを見分けさせないためである。

### 3.3 書体と文字の大きさ

| 名前 | 書体 | 太さ | 使いどころ |
|---|---|---|---|
| `font-sans` | Noto Sans JP。ないときは Hiragino Sans、Yu Gothic、sans-serif の順 | 400、700 | 本文、ボタン、入力欄 |
| `font-serif` | Shippori Mincho B1。ないときは Yu Mincho、serif の順 | 600、800 | 見出し、ボスの名前、大きく見せる数 |
| `font-display` | Cinzel。ないときは `font-serif` | 500、700 | 英字の飾り(`NIGHTREIGN`、`DAY I`、ローマ数字) |

- 書体は Google Fonts から読み込み、`next/font` で自分のサイトから配る。
- `font-display` は英字だけに使う。日本語の文字を持たないためである。
- 英字の飾りは大文字にし、字間を `0.18em` 空ける。

文字の大きさは次の 7 段だけを使う。

| 名前 | 大きさ | 行の高さ | 使いどころ |
|---|---|---|---|
| `text-xs` | 12px | 1.6 | 注記、英字の飾り |
| `text-sm` | 14px | 1.7 | 補足、欄の下のエラー |
| `text-base` | 16px | 1.8 | 本文、入力欄、ボタン |
| `text-lg` | 18px | 1.6 | パネルの見出し |
| `text-xl` | 22px | 1.4 | 節の見出し、大きく見せる数 |
| `text-2xl` | 28px | 1.3 | 画面の題 |
| `text-3xl` | 36px から 48px。画面の幅に合わせて変わる | 1.2 | トップの題 |

- 12px より小さい文字を使わない。
- 入力欄の文字は 16px にする。小さいと、iPhone の Safari が入力のときに画面を拡大するためである。

### 3.4 余白、枠、装飾、動き

- 余白は 4px の倍数(4、8、12、16、24、32、48)だけを使う。
- 角は丸めない(`rounded-none`)。ただし、パターンの番号の丸と、トグルのつまみは丸にする。
- 枠は 1px にする。
- 影は使わず、光で浮かせる。主なパネルに `0 0 24px rgba(201, 164, 92, 0.06)` の外の光を付ける。

装飾は次の 3 つだけを使う。

| 装飾 | 形 | 使う所 |
|---|---|---|
| 飾り枠 | パネルの四隅に、長さ 12px の `gold-deep` の鉤形の線 | 条件のパネル、マップの枠、ダイアログ |
| 飾りの区切り線 | 両端が透けて消える `gold-deep` の 1px の線。中央に小さな菱形(◆) | 節の区切り、画面の題の下 |
| 選んだ行の光 | 左の端に 2px の `gold` の線と、左から右へ透けていく金の帯 | 一覧で選んだ行、選んだスロット |

動きの決まりは次のとおりとする。

- 長さは 150ms から 250ms、`ease-out` とする。
- 動かすのは色、透明度、光の強さだけにする。位置と大きさを動かさない。ただしボトムシートの出し入れは除く。
- 利用者が動きを減らす設定(`prefers-reduced-motion`)にしているときは、すべての動きを止める。

### 3.5 画面の幅の区切り

| 区切り | 幅 | 並べ方 |
|---|---|---|
| 狭い | 767px まで | マップを幅いっぱいに出し、操作はボトムシートに入れる |
| 広い | 768px から | 左に幅 360px の操作のパネル、右にマップ |

幅 360px で、横にはみ出さずに表示できるようにする。

### 3.6 全体のレイアウト

#### ヘッダー

- 高さは 56px とし、上に固定する。
- 左に英字の飾り `NIGHTREIGN` と、日本語の題「収縮パターン帳」を並べる。
- 右に入口を 3 つ置く。「パターン」(`/`)、「記録する」(`/record`)、「ビルド」(`/build`)。
- 今いる画面の入口は `gold` の文字にし、下に 2px の `gold` の線を引く。`aria-current="page"` を付ける。
- 管理の画面(`/admin`)の入口はヘッダーに出さない。
- 狭い幅では、3 つの入口を文字だけの短い名前にして、横に並べたまま収める。

#### 本文

- パネルの見出しは `font-serif` の `gold-bright` にし、その上に英字の飾りを `text-xs` の `ash-soft` で置く。例: 英字 `CONDITIONS`、見出し「条件」。
- 本文の最大の幅は決めない。マップが幅を使うためである。ビルドシミュレーターだけ、最大 1,200px にする。

### 3.7 共通の部品

部品は `frontend/src/components/ui/` に置く。
画面ごとに同じ部品を作り直さない。

| 部品 | 中身 |
|---|---|
| `Panel` | `night-raised` の地と `line` の枠のパネル。`ornate` を付けると飾り枠が出る |
| `SectionHeading` | 英字の飾りと日本語の見出しの組 |
| `OrnateDivider` | 飾りの区切り線 |
| `Button` | 主(`primary`)、副(`secondary`)、危険(`danger`)、文字だけ(`ghost`)の 4 種 |
| `Select` | 選択の欄。ボスと地変の選択に使う。画像の小さい版を添えられる |
| `SegmentedControl` | 2 から 4 の選択肢を横に並べた切り替え。1 日目と 2 日目の切り替えに使う |
| `Badge` | 短い印。記録の数、DLC |
| `PatternChip` | パターンの番号の丸。色と番号を持つ |
| `Toast` | 画面の下に出す短い知らせ。保存の成功と失敗に使う |
| `BottomSheet` | 狭い幅の操作の枠。畳んだ状態と開いた状態を持つ |
| `Skeleton` | 骨組みの表示 |
| `EmptyState` | 空のときの文言と、次の操作の入口 |
| `ErrorNotice` | エラーの知らせ。`ember-soft` の地、`ember` の枠、`ash` の文字 |

#### ボタン

| 種類 | 地 | 文字 | 枠 | 触れたとき |
|---|---|---|---|---|
| 主 | `gold` | `night` | なし | 地を `gold-bright` にし、外の光を強める |
| 副 | 透明 | `ash` | `line-strong` | 枠と文字を `gold` にする |
| 危険 | 透明 | `ember` | `ember` | 地を `ember-soft` にする |
| 文字だけ | 透明 | `gold` | なし | 下線を出す |

- 高さは 44px 以上にする。指で押しやすくするためである。
- 使えない状態は、文字を `ash-soft` にし、枠を `line` にする。透明度で薄くしない。
- 1 つの画面の 1 つの区画に、主のボタンは 1 つまでとする。

#### どの部品にも共通する状態

| 状態 | 表し方 |
|---|---|
| フォーカス | 2px の `gold-bright` の輪郭を、2px 離して出す。`:focus-visible` だけで出す |
| 選んだ状態 | 選んだ行の光(3.4)。色だけでなく、`aria-selected` か `aria-pressed` を付ける |
| 使えない | 3.7 のボタンの決まりと同じ |

### 3.8 マップ

マップは react-konva で描き、サーバー側では描かない(`dynamic` の `ssr: false`)。

| 項目 | 決まり |
|---|---|
| 座標 | 1024 四方の座標空間で描く。表示の大きさに合わせて全体を縮める |
| 画像 | `frontend/public/map/` の画像(1000 px 四方)を、座標空間いっぱいの 1024 四方に引き伸ばして敷く。画像の背景は透けているので、下に `night` より暗い地を敷く |
| 拡大 | ホイールとピンチで 0.3 倍から 3 倍 |
| 移動 | ドラッグ |
| 大きさ | 親の要素の大きさに合わせる(`ResizeObserver`) |
| 枠 | 飾り枠の付いたパネルに入れる |
| 地変 | 地変を選ぶと、その地変の画像に替える(データベースの共通仕様 5.6) |
| 文字 | 地図は明るいので、マップの上の文字には `night` の縁取り(4px)を付ける |

マップの上の印は次のとおりとする。

| 印 | 形 | 色 |
|---|---|---|
| 収縮候補地 | 中心の丸の印(半径 16)と名前。記録とマスタの管理の画面で使い、パターン検索では出さない | 印の線は `tide` の 3px。選んだものは印を `tide` で塗る |
| 選んだ収縮の円 | 実際の半径の円。中は塗らない。円の中は動ける場所だからである | 線は `tide` の 3px。パターン検索ではパターンの色 |
| 選んだ収縮の円の外 | 円の外を塗る。縁は 10px ぼかし、外へ向けて暗くする。円が 2 つあるときは、どちらの円にも入らない所を塗る | `#0b0920` の不透明度 0.72。夜の雨に飲まれた側を表す |
| パターンの収縮先 | 選んだパターンの第 1 次の円と第 2 次の菱形。開始地点から日の順に線でつなぐ | パターンの色。円の中心に日の丸 |
| 第二収縮地点 | 菱形 | `tide` |
| 開始地点 | `frontend/public/icons/zones/spawn.webp` のアイコン。選んだものは大きくし、`gold-bright` の輪で囲む | 選んでいないものは不透明度 0.45 |
| 拠点候補地 | 「?」の丸。拠点の種類は扱わない | 枠は `line-strong` |

マップは、キーボードと読み上げソフトで操作できない。
そのため、マップで選べるものは、パネルの中の一覧からも同じように選べるようにする。

### 3.9 読み込み中、空、エラー、保存中

| 状態 | 表し方 |
|---|---|
| 読み込み中 | 内容が入る場所に `Skeleton` を出す。300ms より早く終わったら出さない。マップは枠だけ先に出す |
| 空 | `EmptyState` に、何がないかと、次にできることを書く。例: 「この条件の記録はまだありません」と「この条件で記録する」の入口 |
| エラー | 内容が入る場所に `ErrorNotice` を出し、「もう一度読み込む」のボタンを置く |
| 保存中 | 押したボタンを使えない状態にし、文字を「保存しています」に替える |
| 保存できた | `Toast` に `grace` の印と「記録を保存しました」を出す。4 秒で消す |

`Toast` は `role="status"`、`ErrorNotice` は `role="alert"` にする。

### 3.10 API のクライアントとエラー

- API は `frontend/src/lib/api.ts` の axios のクライアントだけから呼ぶ。部品から直接呼ばない。
- 取得はフック(`frontend/src/hooks/`)に切り出す。部品はフックの返す `data`、`loading`、`error` を使う。
- クライアントは、エラーの応答から `message` を取り出した `ApiError`(状態の数と `message` を持つ)を投げる。
- 画面は、状態ごとに次の文言を出す。

| 状態 | 出す文言 |
|---|---|
| 400、404、409 | 応答の `message` をそのまま出す |
| 401(管理用の API) | 鍵の入力の欄に戻し、「管理用の鍵が違います」と出す([マスタの管理](master-admin.md) 3.1) |
| 401(それ以外)、403 | 「この操作は許可されていません」 |
| 429 | 応答の `message` をそのまま出す |
| 500 | 「サーバーで問題が起きました。時間をおいてやり直してください」 |
| 502、504、通信の失敗、期限切れ | 「サーバーに接続できません。時間をおいてやり直してください」 |
| 503 | 応答の `message` をそのまま出す。例: 「マスタのサービスに接続できません。時間をおいてやり直してください」 |

### 3.11 アクセシビリティ

- すべての操作を、キーボードだけで行えるようにする。マップの操作は 3.8 のとおり一覧で代える。
- 画像には代替の説明を付ける。飾りの画像は `alt=""` にする。
- 色だけで状態を伝えない。選んだ状態には印か文字を添える。
- 文字を 200% まで大きくしても、内容が欠けない。
- ページごとに `h1` を 1 つ置く。

### 3.12 ディレクトリと名前

```
frontend/src/
├── app/                      # ページ。page.tsx は部品を並べるだけにする
├── components/
│   ├── ui/                   # 共通の部品
│   ├── layout/               # ヘッダー、ページの枠
│   ├── map/                  # マップと、その上の印
│   ├── pattern/              # パターン検索の部品
│   ├── record/               # プレイ記録の部品
│   ├── build/                # ビルドシミュレーターの部品
│   └── admin/                # マスタの管理の部品
├── hooks/                    # use<名前>.ts
├── lib/                      # api.ts、計算、対応表
└── types/                    # API の型
```

- 部品のファイルの名前は PascalCase、フックは `use` で始まる camelCase にする。
- 色、書体、余白の値は `frontend/src/app/globals.css` の `@theme` に書く。部品の中で値を直接書かない。
- 今の `components/sidebar/` は、段階 3 で `components/pattern/` と `components/record/` に分ける。

## 7. 受け入れ条件

### 見た目と幅

| 識別子 | 条件 |
|---|---|
| `AC-UI-01` | 部品のファイル(`components/`)に、`#` で始まる色の値と `bg-[` の任意の値の指定がない。マップの描画で Konva に渡す値は、`lib/theme.ts` の定数から取る |
| `AC-UI-02` | 幅 360px で 4 つの画面を開くと、横のスクロールが出ない |
| `AC-UI-03` | 幅 767px ではマップの下にボトムシートが出て、幅 768px では左に操作のパネルが出る |
| `AC-UI-04` | ページの地の色が `#0e0c0a` で、本文の文字の色が `#e8dfcc` である |
| `AC-UI-05` | 動きを減らす設定にすると、ボタンに触れたときの光の変化が起きない |

### キーボードとアクセシビリティ

| 識別子 | 条件 |
|---|---|
| `AC-UI-06` | Tab キーだけで、ヘッダーの 3 つの入口と、条件のパネルのすべての欄に移れ、フォーカスの輪郭が見える |
| `AC-UI-07` | axe の検査で、4 つの画面に重大度 serious 以上の違反がない |
| `AC-UI-08` | パターンの一覧で、各パターンに色の丸と番号の両方が出る |

### API の失敗

| 識別子 | 条件 |
|---|---|
| `AC-UI-09` | バックエンドを止めた状態でパターン検索の画面を開くと、「サーバーに接続できません。時間をおいてやり直してください」と「もう一度読み込む」のボタンが出る |
| `AC-UI-10` | 404 の応答の `message` が「bossId 'x' は存在しません」のとき、画面にその文言が出る |

## 8. 未決事項

- **書体の読み込みの重さ**: Noto Sans JP と Shippori Mincho B1 の日本語の書体は大きい。使う文字に絞る(サブセット)か、本文を端末の書体に任せるか。段階 3 で、表示までの時間を測って決める。
- **拠点の種類の画像**: `public/images/zones/` の拠点の種類の画像(砦、教会など)は、拠点の種類を記録しないことにした(決定の記録 [0010](../decisions/0010-night-boss-in-record.md))ので、使う所がない。消すか、マスタの管理で拠点候補地の印に使うかを、段階 3 で利用者が決める。
- **ボスと地変の画像**: `public/images/bosses/` と `jihen/` は空である。画像を置くかは、段階 3 で決める。置かない間は、名前の頭文字を `font-serif` で出す。
- **見た目の試作の承認**: [画面の一覧と遷移](screens.md) の試作を利用者が見て、方針を承認してから段階 3 に入る。
