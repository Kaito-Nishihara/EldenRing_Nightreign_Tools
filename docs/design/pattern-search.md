# 機能設計: パターン検索

## 1. 目的

プレイヤーが、夜の王、開始地点、地変を選ぶと、同じ条件で過去に記録された収縮先を、パターンにまとめてマップで見られる。
何回中何回そのパターンだったかで、今回の収縮先の見当を付けられる。

## 2. 範囲

やること:

- 条件の選択
- 記録をパターンにまとめる決まりと並び順
- パターンの一覧とマップへの描き方
- 収縮先ごとの出現の回数(要件定義の旧 F6)

やらないこと:

- 収縮先の予測の計算
- 条件の一部だけが合う記録の表示(例: 地変を問わない検索)
- 記録の一覧を 1 件ずつ見ること
- 夜ボスでの絞り込みと、夜ボスの表示(決定の記録 [0010](../decisions/0010-night-boss-in-record.md))

### この文書で使う言葉

| 言葉 | 意味 |
|---|---|
| 条件 | 夜の王、開始地点、地変の組。地変は「なし」を含む |
| 収縮先の並び | 1 件の記録が持つ、日と段階と収縮先の組の集まり。日と段階の順に並べたもの。収縮先は、第 1 次では収縮候補地、第 2 次では第二収縮地点である |
| パターン | 収縮先の並びがまったく同じ記録の集まり |

## 3. 画面

パス: `/`
試作: [画面: パターン検索](../screens/pattern.md)

### 3.1 条件

| 欄 | 選び方 | 必須 |
|---|---|---|
| 夜の王 | 頭文字と名前のボタンを 2 列に並べる。初めは 6 体を出し、「ほかの 4 体を表示」で残りを出す | はい |
| 地変 | 選択の欄。初めの値は「なし」 | いいえ |
| 開始地点 | 選択の欄。マップの開始地点のアイコンを押しても選べる | はい |

- 夜の王と開始地点がそろうと、すぐに検索する。検索のボタンを置かない。
- 条件を変えると検索し直す。前の検索の応答が後から届いても、画面に出さない。
- 選んだ条件は URL のクエリに残す([画面の一覧と遷移](screens.md) 3.2)。

### 3.2 パターンの一覧

一覧の上に「この条件の記録 6 件、3 パターン」と出す。

カード 1 枚に次を出す。

| 項目 | 例 | 決まり |
|---|---|---|
| 番号の丸 | ① | パターンの色の丸に番号。番号は並び順 |
| 題 | 最北 → 最南東 | 1 日目と 2 日目の第 1 次収縮の場所。片方がないときは「未記録」 |
| 記録の数 | 3 回 | 1 番のパターンだけ `gold` の枠の印にする |
| 収縮先 | DAY I 第 1 次 最北 ／ 第 2 次 最北 | 日ごとに 1 行。記録のない段階は出さない |
| 割合の帯 | 帯の長さ 50% | 記録の数を、条件の記録の総数で割った値 |
| 補足 | 6 回中 3 回、最後の記録 2026-10-12 | 日付は日本時間 |

- 並びは記録の数の多い順、同じ数なら最後の記録の新しい順とする。
- 初めは 1 番のパターンを選んだ状態にする。カードを押すと、そのパターンを選ぶ。
- 1 つの条件のパターンが 8 を超えたときは、9 番目からも同じ 8 色を繰り返し、番号で見分ける。

### 3.3 マップ

マップには、選んだパターンで実際に起きた収縮だけを出す。
収縮候補地の円(12 か所)と、選んでいないパターンは出さない。

- 開始地点をアイコン(共通仕様 3.8)で出す。選んでいない開始地点は薄く出す。
- 第 1 次の収縮先を、その収縮候補地の中心と半径の円で、パターンの色で出す。円の中心に日(I、II)の丸を置き、円の上に「DAY I 最北」の形で名前を出す。
- 第 2 次の収縮先を、パターンの色の菱形で出し、同じ日の第 1 次の中心と細い破線でつなぐ。第 1 次を記録していない日は、菱形だけを出す。
- カードを押すと、マップをそのパターンの収縮先に替える。
- マップの上の「すべて」「DAY I」「DAY II」で、出す日を絞る。初めは「すべて」とする。
- 「すべて」のときは、開始地点から 1 日目、2 日目の第 1 次の中心へ、パターンの色の線でつなぐ。
- 円の中は塗らず、円の外を夜の雨の暗がり(共通仕様 3.8)で塗る。円の中は動ける場所だからである。「すべて」のときは、2 つの円のどちらにも入らない所を塗る。

### 3.4 状態

| 状態 | 出すもの |
|---|---|
| 条件がそろっていない | 一覧の場所に「夜の王と開始地点を選ぶと、過去のパターンが出ます」 |
| 読み込み中 | カード 2 枚分の骨組みの表示 |
| 記録がない | 「この条件の記録はまだありません」と「この条件で記録する」のボタン |
| エラー | 共通仕様 3.9 と 3.10 のとおり |

## 4. API

### `GET /api/v1/patterns`

受け持ち: `record-service`
必要な役割: なし

**入力(クエリ)**

| 名前 | 型 | 必須 | 決まり |
|---|---|---|---|
| `bossId` | 文字列 | はい | `bosses` にある識別子 |
| `spawnPointId` | 整数 | はい | `spawn_points` にある識別子 |
| `jihenId` | 文字列 | いいえ | 省くと地変なしの記録だけを探す |

**出力(200)**

```json
{
  "totalRecords": 6,
  "patterns": [
    {
      "patternIndex": 1,
      "recordCount": 3,
      "lastRecordedAt": "2026-10-12T11:20:00Z",
      "entries": [
        {
          "day": 1, "phase": 1,
          "zone": { "id": 4, "nameJa": "最北", "centerX": 583.0, "centerY": 297.0, "radius": 150.0 },
          "secondShrinkPoint": null
        },
        {
          "day": 1, "phase": 2,
          "zone": null,
          "secondShrinkPoint": { "id": 4, "nameJa": "最北", "x": 583.0, "y": 297.0 }
        }
      ]
    }
  ]
}
```

- `patterns` は 3.2 の並び順で返し、`patternIndex` は 1 から振る。
- `entries` は日、段階の順に並べる。
- 第 1 次の収縮先は `zone` に、第 2 次の収縮先は `secondShrinkPoint` に入れ、もう一方は `null` にする。
- 記録がないときは `{ "totalRecords": 0, "patterns": [] }` を返す。404 にしない。

**エラー**

| 状態 | 条件 | `message` の例 |
|---|---|---|
| 400 | `bossId` か `spawnPointId` がない。`spawnPointId` が整数でない | `spawnPointId は必須です` |
| 404 | `bossId`、`spawnPointId`、`jihenId` の行がない | `bossId 'unknown' は存在しません` |
| 503 | `master-service` が応答しない | `マスタのサービスに接続できません。時間をおいてやり直してください` |

まとめる処理は `record-service` で行う。
条件で絞った記録を読み、収縮先の並びを鍵にしてまとめる。
収縮先の名前と座標は、まとめた後に、出てきた識別子だけを `master-service` の内部の API([マスタの管理](master-admin.md) 4.4)で引いて入れる。
非表示の収縮候補地と第二収縮地点も、名前と座標で返す。
条件の夜の王、開始地点、地変があるかも、同じ問い合わせで確かめる。

## 5. データ

読むだけで、書かない。

| テーブル | 使う列 |
|---|---|
| `play_records` | `boss_id`、`spawn_point_id`、`jihen_id`、`created_at` |
| `shrink_entries` | `play_record_id`、`day`、`phase`、`zone_id`、`second_shrink_point_id` |
| `shrink_zones` | すべて |
| `second_shrink_points` | すべて |

## 6. サービスの間のやり取り

画面 → Gateway → `record-service` → `master-service` の順に呼ぶ。
`record-service` か `master-service` が応答しないときは、共通仕様 3.10 のとおり出す。
`master-service` への問い合わせは、1 回の検索につき 1 回とする。

## 7. 受け入れ条件

| 識別子 | 条件 |
|---|---|
| `AC-PAT-01` | 同じ条件で、収縮先の並びが同じ記録が 3 件、別の並びが 1 件あるとき、パターンが 2 つ返り、1 番目の `recordCount` が 3 である |
| `AC-PAT-02` | 記録の数が同じ 2 つのパターンは、最後の記録の新しい方が先に並ぶ |
| `AC-PAT-03` | `patternIndex` が、並び順に 1、2、3 と振られている |
| `AC-PAT-04` | `jihenId` を省いて検索すると、地変ありの記録が数に入らない |
| `AC-PAT-05` | `jihenId=crater` で検索すると、地変なしの記録が数に入らない |
| `AC-PAT-06` | 記録のない条件で検索すると、200 と `{ "totalRecords": 0, "patterns": [] }` が返る |
| `AC-PAT-07` | 1 日目の第 1 次だけを記録したものと、1 日目の第 1 次と第 2 次を記録したものは、第 1 次の場所が同じでも別のパターンになる |
| `AC-PAT-08` | `spawnPointId` を省くと 400 が返る |
| `AC-PAT-09` | 存在しない `bossId` で検索すると 404 が返る |
| `AC-PAT-10` | 画面で夜の王と開始地点を選ぶと、検索のボタンを押さずにパターンの一覧が出る |
| `AC-PAT-11` | 6 件中 3 件のパターンのカードに「6 回中 3 回」と出て、割合の帯の長さが 50% である |
| `AC-PAT-12` | 2 番目のカードを押すと、マップに 2 番のパターンの収縮先だけが出て、1 番のパターンの円と線が消える |
| `AC-PAT-13` | 記録のない条件では「この条件の記録はまだありません」と「この条件で記録する」のボタンが出る |
| `AC-PAT-14` | 条件を素早く 2 回変えたとき、最後に選んだ条件の結果だけが出る |
| `AC-PAT-15` | 1 日目の第 1 次が同じで、第 2 次の第二収縮地点が違う 2 件の記録は、別のパターンになる |
| `AC-PAT-16` | 第 2 次の収縮先は、`zone` が `null` で、`secondShrinkPoint` に地点の `id`、`nameJa`、`x`、`y` が入って返る |
| `AC-PAT-17` | 1 日目が「最北」、2 日目が「最南東」のパターンを選ぶと、マップの円は「最北」と「最南東」の 2 つだけで、ほかの収縮候補地の円が出ない |
| `AC-PAT-18` | 「DAY I」を押すと、1 日目の円だけが出て、その円の外が暗がりで塗られる |
| `AC-PAT-19` | 「すべて」では、1 日目と 2 日目の円の中は塗られず、どちらの円にも入らない所だけが暗がりで塗られる |
| `AC-PAT-20` | `master-service` が応答しない状態で検索すると 503 が返る |
| `AC-PAT-21` | 非表示にした収縮候補地を含むパターンも、その収縮候補地の名前と座標が入って返る |

## 8. 未決事項

- **夜ボスの表示**: 記録が持つ夜ボスを、パターンのカードに出すか(例: 「1 日目の夜ボス 鈴玉狩り 2 回」)。記録が集まってから利用者が決める。
- **記録の件数が多い条件の速さ**: 1 つの条件の記録をすべて読んでまとめている。1 つの条件で数百件を超えたら、データベースでまとめる形を考える。今の件数では測っていない。
