# 機能設計: プレイ記録

## 1. 目的

プレイヤーが、プレイ中に収縮の起きた場所をマップで選び、プレイの後に 1 件の記録として保存できる。
保存した記録は、すぐにパターン検索に入る。

## 2. 範囲

やること:

- 収縮先の入力(1 日目と 2 日目、第 1 次と第 2 次の 4 つのスロット)。第 1 次は収縮候補地、第 2 次は第二収縮地点で選ぶ
- 1 日目と 2 日目の夜ボスの入力(任意)
- 入力中の内容を端末に残すこと
- 保存の検証と保存の後の動き

やらないこと:

- 記録の修正と削除(決定の記録 [0005](../decisions/0005-keep-play-records.md))
- 通信が切れている間の保存の待ち合わせ(P1 のオフラインでの利用で決める)
- 収縮のタイムライン(P1。この文書の 3.4 は見た目の置き場だけを決める)
- 拠点の種類の入力と、記録の画面での拠点候補地の表示(決定の記録 [0010](../decisions/0010-night-boss-in-record.md))

### この文書で使う言葉

| 言葉 | 意味 |
|---|---|
| スロット | 日と段階の組 1 つ分の入力の欄。`1-1`(1 日目の第 1 次)から `2-2` まで 4 つ |
| 選んでいるスロット | マップを押したときに収縮先が入るスロット |
| 下書き | 入力中の内容。端末の `localStorage` に残す |
| 収縮先 | 第 1 次では収縮候補地(円)、第 2 次では第二収縮地点(点)。決定の記録 [0008](../decisions/0008-second-shrink-by-point.md) |

## 3. 画面

パス: `/record`
試作: [画面: プレイ記録](../screens/record.md)

### 3.1 今回の条件

- 夜の王、地変、開始地点を選ぶ。選び方はパターン検索と同じである。
- パターン検索から移ったときは、その条件が選ばれている。
- 条件を選んだ後は、頭文字と名前だけの短い表示に畳み、「変える」で開く。

### 3.2 スロット

- 4 つのスロットを、DAY I と DAY II に分けて並べる。
- 初めは `1-1` を選んでいる状態にする。
- 第 1 次のスロットを選んでいるときは、マップの収縮候補地を押して入れる。第 2 次のスロットを選んでいるときは、第二収縮地点を押して入れる。
- 入れると、そのスロットに名前が入り、`1-1`、`1-2`、`2-1`、`2-2` の順で次の空いたスロットを選ぶ。空いたスロットがなければ、どれも選んでいない状態にする。
- 入れたスロットを押すと、そのスロットを選び直せる。もう一度マップを押すと、入れ替わる。
- スロットには「✓」の印と名前を出す。色だけで入れたことを示さない。
- マップを使えない人のために、選んでいるスロットの収縮先を一覧から選ぶ欄を置く。第 1 次では収縮候補地、第 2 次では第二収縮地点を並べる。
- DAY I と DAY II のそれぞれに、夜ボスの選択の欄を置く。その日の夜ボスだけを並べ、初めの値は「選ばない」とする。
- 入れた数を「1 / 4」の形で出す。

狭い画面では、ボトムシートを畳んだときにも、取っ手に「DAY I 第 2 次を入力中」の形で選んでいるスロットを出す。
マップを押す間、シートを開かなくてよいようにするためである。

### 3.3 マップ

- 選んでいるスロットの日に合わせて、DAY I と DAY II を切り替える。
- 収縮候補地は、中心の丸の印と名前で出す(共通仕様 3.8)。実際の大きさの円は重なって押せないので、選んだ収縮先だけを円で出す。
- 第 1 次のスロットを選んでいるときは、収縮候補地の印を押せる状態で出し、第二収縮地点は出さない。
- 第 2 次のスロットを選んでいるときは、第二収縮地点の菱形を押せる状態で出し、収縮候補地の印は押せない薄い印にする。同じ日の第 1 次を入れていれば、その円の中の地点を濃く、外の地点を不透明度 0.4 で出す。外の地点も押せる。座標がダミーの間は、円の中かどうかで選べるものを絞らないためである。
- 選んだ第 1 次の円を実際の大きさで出し、円の外を夜の雨の暗がり(共通仕様 3.8)で塗る。円の中は塗らない。
- 「収縮を表示」と「隠す」で、収縮候補地の円と暗がりを同時に出し入れする。
- 開始地点をアイコン(共通仕様 3.8)で出す。拠点候補地は出さない。

### 3.4 収縮のタイムライン(P1)

スロットの上に、次の収縮までの残り時間と、経過の帯を置く。
動き(始める、止める、日の切り替え)は P1 の仕様書で決める。
P1 までは、この区画を出さない。

### 3.5 備考と保存

- 備考は任意で、500 文字までとする。超えたら入力を止めずに、欄の下に「500 文字までです(今 523 文字)」と出し、保存できなくする。
- 「記録を保存する」は、夜の王と開始地点を選び、スロットを 1 つ以上入れたときに使える。使えないときは、ボタンの下に足りないものを出す。例: 「収縮先を 1 つ以上入れてください」
- 保存に成功したら、知らせ(共通仕様 3.9)に「記録を保存しました」と「パターンを見る」を出し、下書きを消し、スロットと夜ボスと備考を空にする。条件は残す。続けて同じ条件を記録しやすくするためである。
- 「やり直す」は、確かめの枠を出してから、スロットと夜ボスと備考を空にする。

### 3.6 下書き

- 入力が変わってから 1 秒後に、下書きを `localStorage` の `nightreign_play_record_draft` に書く。
- 画面を開いたときに下書きがあれば戻し、「前回の入力を戻しました」と知らせる。
- 下書きの形が読めないときは捨てる。
- 下書きには版の番号(`version: 2`)を持たせる。版の違う下書きは、戻さずに捨てる。旧版の画面の下書きは第 2 次を収縮候補地で持っていて、今の形と合わないためである。

## 4. API

### `POST /api/v1/play-records`

受け持ち: バックエンド
必要な役割: なし

**入力**

```json
{
  "bossId": "gladius",
  "jihenId": null,
  "spawnPointId": 1,
  "day1NightBossId": 3,
  "day2NightBossId": null,
  "note": "2 日目は地変の方へ寄った",
  "entries": [
    { "day": 1, "phase": 1, "zoneId": 4, "secondShrinkPointId": null },
    { "day": 1, "phase": 2, "zoneId": null, "secondShrinkPointId": 4 },
    { "day": 2, "phase": 1, "zoneId": 7, "secondShrinkPointId": null }
  ]
}
```

| 項目 | 決まり |
|---|---|
| `bossId` | 必須。`bosses` にある |
| `jihenId` | 任意。`null` は地変なし。値があれば `jihen` にある |
| `spawnPointId` | 必須。`spawn_points` にある |
| `day1NightBossId` | 任意。値があれば `night_bosses` にあり、`day` が 1 である |
| `day2NightBossId` | 任意。値があれば `night_bosses` にあり、`day` が 2 である |
| `note` | 任意。前後の空白を除いて 500 文字まで。空の文字列は `null` として保存する |
| `entries` | 必須。1 件以上 4 件以下 |
| `entries[].day` | 1 か 2 |
| `entries[].phase` | 1 か 2 |
| `entries[].zoneId` | `phase` が 1 のとき必須で、`shrink_zones` にある。`phase` が 2 のときは `null` |
| `entries[].secondShrinkPointId` | `phase` が 2 のとき必須で、`second_shrink_points` にある。`phase` が 1 のときは `null` |
| `day` と `phase` の組 | 1 つの記録の中で重複しない |

**出力(201)**

```json
{ "id": 42, "createdAt": "2026-10-17T12:34:56Z" }
```

**エラー**

| 状態 | 条件 | `message` の例 |
|---|---|---|
| 400 | 形の誤り(必須がない、範囲の外、文字数の超過、`entries` が空か 5 件以上) | `entries は 1 件以上 4 件以下です` |
| 400 | `day` と `phase` の組が重複する | `day=1, phase=1 が重複しています` |
| 400 | 段階と収縮先の種類が合わない | `day=1, phase=2 は secondShrinkPointId で指定してください` |
| 400 | 夜ボスの日が合わない | `day1NightBossId には 1 日目の夜ボスを指定してください` |
| 404 | 参照する行がない | `zoneId '99' は存在しません` |

検証に失敗したときは、何も保存しない。
記録と収縮先は、1 つのトランザクションで保存する。

### 画面が使う取得の API

| メソッドとパス | 使う所 |
|---|---|
| `GET /api/v1/shrink-zones` | 第 1 次のスロット |
| `GET /api/v1/second-shrink-points` | 第 2 次のスロット。旧版では管理用のパスでしか取れなかったので、プレイヤー向けのパスを足す |
| `GET /api/v1/night-bosses` | 夜ボスの選択の欄 |

出力の形は [マスタの管理](master-admin.md) の 4.1 に書く。

## 5. データ

持ち主: バックエンド

**`play_records`**

| 列 | 型 | 制約 |
|---|---|---|
| `id` | integer | 主キー |
| `boss_id` | varchar(50) | `NOT NULL`。`bosses` を参照 |
| `jihen_id` | varchar(50) | `jihen` を参照。`NULL` は地変なし |
| `spawn_point_id` | integer | `NOT NULL`。`spawn_points` を参照 |
| `day1_night_boss_id` | integer | `night_bosses` を参照。`NULL` は選ばなかった |
| `day2_night_boss_id` | integer | `night_bosses` を参照。`NULL` は選ばなかった |
| `note` | varchar(500) | |
| `created_at` | timestamptz | `NOT NULL` |

旧版では `spawn_point_id` が `NULL` を許していた。
入力では必須なので、新しいスキーマでは `NOT NULL` にする。

**`shrink_entries`**

| 列 | 型 | 制約 |
|---|---|---|
| `id` | integer | 主キー |
| `play_record_id` | integer | `NOT NULL`。`play_records` を参照。`ON DELETE CASCADE` |
| `day` | integer | `NOT NULL`。1 か 2 |
| `phase` | integer | `NOT NULL`。1 か 2 |
| `zone_id` | integer | `shrink_zones` を参照 |
| `second_shrink_point_id` | integer | `second_shrink_points` を参照 |

`(play_record_id, day, phase)` に一意の制約を付ける。
`phase` が 1 なら `zone_id` だけ、2 なら `second_shrink_point_id` だけを持つ検査の制約を付ける。

夜ボスの日が合っているかは、データベースの制約にせず、サービスで確かめる。
`night_bosses` の `day` を見る制約は、別のテーブルを参照する検査になるためである。

## 6. サービスの間のやり取り

画面 → Gateway → バックエンドの順に呼ぶ。
保存の要求が期限切れか通信の失敗で終わったときは、下書きを残したまま「保存できませんでした。入力は残っています。時間をおいてもう一度保存してください」と出す。
応答が届かなかったが実際には保存されていた場合、もう一度保存すると記録が 2 件になる。
これを防ぐ仕組みは、今は持たない(8 章)。

## 7. 受け入れ条件

| 識別子 | 条件 |
|---|---|
| `AC-REC-01` | 正しい入力で保存すると 201 と `id`、`createdAt` が返り、`play_records` に 1 行、`shrink_entries` に `entries` の数の行が入る |
| `AC-REC-02` | `entries` が空の配列だと 400 が返り、何も保存されない |
| `AC-REC-03` | `entries` に `day=1, phase=1` が 2 つあると 400 が返り、`message` が「day=1, phase=1 が重複しています」である |
| `AC-REC-04` | 存在しない `zoneId` を含むと 404 が返り、`play_records` に行が増えない |
| `AC-REC-05` | 存在しない `jihenId` を指定すると 404 が返る |
| `AC-REC-06` | 501 文字の `note` を送ると 400 が返る |
| `AC-REC-07` | `note` が空白だけのとき、`note` が `NULL` で保存される |
| `AC-REC-08` | 保存した直後に同じ条件でパターン検索をすると、`totalRecords` が 1 増えている |
| `AC-REC-09` | 画面で `1-1` を選んでいる状態で収縮候補地「最北」を押すと、`1-1` に「最北」が入り、`1-2` が選ばれる |
| `AC-REC-10` | 4 つのスロットをすべて入れると、どのスロットも選ばれていない状態になる |
| `AC-REC-11` | スロットを 1 つ入れて再読み込みすると、入れた内容が戻り、「前回の入力を戻しました」と出る |
| `AC-REC-12` | スロットを 1 つも入れていないとき、「記録を保存する」が使えず、「収縮先を 1 つ以上入れてください」と出る |
| `AC-REC-13` | 保存に成功すると、スロットと備考が空になり、条件は残り、下書きが消える |
| `AC-REC-14` | バックエンドを止めて保存すると、「保存できませんでした。入力は残っています。時間をおいてもう一度保存してください」と出て、スロットの内容が残る |
| `AC-REC-15` | 一覧から選ぶ欄を使い、キーボードだけで 4 つのスロットを入れて保存できる |
| `AC-REC-16` | `phase=2` の収縮先を `zoneId` で送ると 400 が返り、`message` が「day=1, phase=2 は secondShrinkPointId で指定してください」の形である |
| `AC-REC-17` | `phase=1` の収縮先を `secondShrinkPointId` で送ると 400 が返る |
| `AC-REC-18` | 存在しない `secondShrinkPointId` を含むと 404 が返り、`play_records` に行が増えない |
| `AC-REC-19` | `day1NightBossId` に 2 日目の夜ボスを指定すると 400 が返り、`message` が「day1NightBossId には 1 日目の夜ボスを指定してください」である |
| `AC-REC-20` | `day1NightBossId` を指定し、`day2NightBossId` を省いて保存すると、`day1_night_boss_id` に値が、`day2_night_boss_id` に `NULL` が入る |
| `AC-REC-21` | 画面で `1-2` を選んでいる状態で収縮候補地の印を押しても入らず、第二収縮地点を押すとその名前が入る |
| `AC-REC-22` | `version: 1` の下書きが残っている状態で画面を開くと、下書きが消え、「前回の入力を戻しました」が出ない |

## 8. 未決事項

- **第 1 次と第 2 次の対応**: 第二収縮地点がどの収縮候補地の中にあるかを、マスタに持つか。持てば、第 1 次の円の外の地点を拒める。座標が正しくなってから(要件定義の 12 章)、利用者が決める。
- **同じ記録の二重の保存**: 応答が届かなかったときの保存のやり直しで、記録が 2 件になる(6 章)。画面で作った識別子を送り、バックエンドで重複を拒む形にするか。
